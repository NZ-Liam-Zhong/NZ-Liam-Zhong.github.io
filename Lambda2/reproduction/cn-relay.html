Cloud Relay Profile (cn_relay)#

The cloud relay carries both control and video between the operator Mac and the on-robot Jetson.

Which config path to use#

KILN config is migrating to a unified schema. Pick one path and stay on it:

Path

Mac

Jetson

Active for

New (recommended)

config/lambda2.yaml with system.profile: cn_relay

same file (deployed from Mac)

fresh setups

Legacy

client/workstation/configs/site.yaml

config/site.yaml

sites predating the unified config

Legacy setups must keep the Mac and Jetson site.yaml copies identical. During migration, keep all three files (unified entry + both site.yaml copies) pointing at the same region and IPs.

Profile file#

config/profiles/cn_relay.example.yaml  →  config/profiles/cn_relay.yaml (local)

The unified entry references it from config/lambda2.yaml:

system:
  profile: cn_relay

Copy *.example.yaml → remove .example for local use. Real configs stay out of Git.

Setup steps#

cp client/workstation/configs/site.yaml.example client/workstation/configs/site.yaml
# Edit active_region, relay host, thor IP
./client/workstation/scripts/show_site_config.sh

cp config/site.yaml.example config/site.yaml
nano config/site.yaml          # must match Mac
./config/apply_site_config.sh
systemctl --user restart teleop-control-tunnel teleop-rtp

The steps above edit the legacy site.yaml files. New setups instead set system.profile: cn_relay in config/lambda2.yaml and apply the same values there.

Token#

export TELEOP_TOKEN='<your-token>'

Token must match /opt/lambda2-relay/control.env on the relay server. Never commit tokens.

Connect#

  1. ./client/run_workstation_mac.sh

  2. Select Cloud Relay → Connect Agent

  3. Verify arms and video independently — see Control vs video

Operator lease#

Only one primary operator may hold the control lease at a time. A second workstation receives a connection rejection until the first disconnects.
