Lab LAN Direct Mode#

Use direct mode when Mac, Jetson, and the Tianji cabinet are on the same laboratory network without a public cloud relay.

When to use#

  • Initial Jetson bring-up

  • Debugging agent or RTP issues in isolation

  • Sites without stable public relay access

Configuration#

Mac and Jetson site.yaml must stay identical — set both sides to default_mode: direct with the same device IPs.

  1. Copy the site config example:

    cp client/workstation/configs/site.yaml.example client/workstation/configs/site.yaml

  2. Set default_mode: direct and fill local IPs:

    Field

    Example

    devices.thor.host

    Jetson LAN IP

    devices.tianji.robot_ip

    Tianji cabinet IP

    devices.chassis.vmr_host

    VMR IP

  1. Copy the site config example:

    cp config/site.yaml.example config/site.yaml

  2. Set default_mode: direct with the same IPs as the Mac copy.

  3. Point RTP at the operator Mac, apply, and restart:

    export DEST_IP='<mac-lan-ip>'
./config/apply_site_config.sh
systemctl --user restart teleop-rtp teleop-thor-agent

Mac client#

export TELEOP_TOKEN='<your-token>'   # still required if agent enforces auth
./client/run_workstation_mac.sh

Select Direct mode in the workstation if your build exposes mode switching; otherwise site.yaml drives the default.

Verification#

  • ss -ltn | grep -E '15666|8099' on Jetson

  • Arms enable without relay tunnel (or with direct agent path per your profile)

  • Video windows show streams with dest_ip pointing to Mac

  • ./scripts/lambda2 doctor passes for lab_lan profile

You’re done when: GELLO follow works and both camera streams are visible on the Mac over LAN only.

Limitations#

Direct mode does not replicate cross-region latency, TLS relay behavior, or operator lease semantics. Validate those on CN relay profile before field deployment.
