Secrets Management#

KILN separates credentials from version-controlled configuration.

Never commit#

Secret

Where it lives

TELEOP_TOKEN

Environment variable, login UI, relay control.env

AWS access key / secret

secrets.env, aws_env.sh, or IAM role on Jetson

Operator passwords

Issued by administrator, not stored in repo

Local secrets file#

cp config/secrets.env.example config/secrets.env
# Edit locally — file is gitignored

Example contents (placeholders only):

TELEOP_TOKEN=<your-token>
AWS_ACCESS_KEY_ID=<key>
AWS_SECRET_ACCESS_KEY=<secret>

Runtime usage#

Mac client#

export TELEOP_TOKEN='<your-token>'
./client/run_workstation_mac.sh

Jetson services#

export TELEOP_TOKEN='<your-token>'
./services/autostart/install_all.sh

systemd user units inherit environment from install scripts or environment.d snippets on device.

YAML rule#

Do not put tokens or AWS keys in any YAML file, including lambda2.yaml and profiles. Schema references secret paths or profile names only.

Relay server#

Cloud relay validates tokens against /opt/lambda2-relay/control.env. Coordinate token rotation with all operator workstations and Jetson units simultaneously.

If a secret was committed#

  1. Rotate the token/key immediately

  2. Remove from Git history if needed

  3. Update relay and all edge devices with the new value
