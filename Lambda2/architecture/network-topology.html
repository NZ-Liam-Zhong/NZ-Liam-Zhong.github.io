Network Topology#

Typical deployment#

[Mac Operator]  Wi-Fi 172.20.10.x
      │  TLS 8443 (control: agent + chassis)   UDP 5600/5602 (video)
      ▼
[relay-gz.lambdarobotics.ai]
      ▲
      │  TLS 9443 (site tunnel)   RTP ingress
[Jetson 172.20.10.4]
      ├── 192.168.1.190  Tianji dual-arm cabinet
      ├── 127.0.0.1:9100  joystick_receiver ← relay chassis channel (direct mode: Mac connects TCP 9100 directly)
      └── 192.168.100.201  VMR chassis

Relay mode vs direct mode#

Mode

When to use

Video destination

Relay

Cross-site / public internet

Jetson pushes RTP to relay host

Direct

Same LAN debugging

Jetson pushes to operator IP (DEST_IP)

Both modes can coexist in configuration; site.yaml selects the active profile.

Region relay architecture#

[Operator PC]
   ├─ Video: receive forwarded RTP (left/right)
   ├─ Control: TLS+Token → Region agent_proxy → Jetson :15666
   └─ Stream API: TLS+Token → Region stream_api_proxy → Jetson :8099
                │
         [Region node (region-xxx …)]
                │
         [Jetson / site]
           ├─ RTP push → Region
           ├─ Agent :15666
           └─ stream_api :8099

Security decisions (relay product)#

Topic

Decision

Video relay

Cloud RTP passthrough (no transcode)

Control path

TLS + token through region proxy

Multi-operator

Second connection rejected (lease)

E-stop

High priority, still requires valid token

stream_api :8099

Control plane; write access for primary operator only
